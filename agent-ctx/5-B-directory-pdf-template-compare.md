## Implementation details

### PDF generator (`/api/employees/directory-pdf`)
- Uses `pdfkit` (already in package.json + already used in `src/lib/document-renderers.ts`).
- Sets `bufferPages: true` on the PDFDocument so we can call `doc.switchToPage(n)` after rendering to backfill the TOC page numbers + draw footers on every page.
- Page 1 (title): top accent bar (emerald), large centred "Employee Directory" title, company name + address + contact line, decorative emerald separator, "Generated on {date}" + employee/department count.
- Page 2 (TOC): "Table of Contents" header with emerald underline, one row per department with a colored swatch (department.color or emerald fallback), dept name in bold, dotted leader line, employee count subtitle, and page number written in the right column during the backfill pass.
- Pages 3+ (per-department sections): colored header band (department.color or emerald), section name + employee count, then a 7-column table with Photo (initials-in-circle placeholder, no real photo embedding to keep things lightweight), Name, Emp ID, Designation, Email, Phone, Joined. Header row has a gray background and bold labels; body rows have alternating gray stripe for readability; cells are stroked with light gray borders. Long values use `ellipsis: true` to fit. Auto page-breaks with a compact "(continued)" header band + repeated table header when a section overflows one page.
- Footers (pages 2+): top border line + "Generated by TeamHub HR" on the left + "Page X of Y" on the right (skipped on the title page since it has its own design).
- Two-pass approach: render title page → render TOC skeleton with blank page-number column → render each department section, recording `startPage = doc.bufferedPageRange().count` for each → switch back to page index 1 (TOC) and write the real page numbers → loop over all pages and draw footers.
- Query: pulls all employees with `include: { department, role, designation }`, ordered by department name then employee ID, grouped in-memory into a `Map<string, DeptSection>` (department name → section). Employees with no department go into a "— No Department —" section.
- Filter support: `?departmentId=...` and `?status=...` query params are forwarded directly to the Prisma `where` clause.
- Response: `Content-Type: application/pdf`, `Content-Disposition: attachment; filename="employee-directory-{YYYY-MM-DD}.pdf"`, `Cache-Control: no-store`.
- Writes a single `EMPLOYEE_DIRECTORY_PDF` audit log entry (best-effort, wrapped in try/catch).

### Diff API (`/api/document-templates/compare`)
- Classic LCS (Longest Common Subsequence) dynamic programming on lines:
  - Build an `(n+1) × (m+1)` table of LCS lengths using `Uint32Array` rows for speed.
  - Backtrack from `[n][m]` to produce a sequence of `{ type: "added" | "removed" | "unchanged", line, lineNum }` entries that reconstruct both inputs.
- `content` and `emailBody` use the line-diff routine (split on `\n` after normalising CRLF).
- `subject` and `emailSubject` use a token-level diff (tokenise on `\S+\s*` so spaces stay attached). Same LCS routine but on token arrays.
- Response shape (matches the spec):
  ```ts
  {
    template1: { id, name, code, type, category, version, status, subject, content, emailSubject, emailBody, updatedAt },
    template2: { ... },
    contentDiff: LineDiffEntry[],
    subjectDiff: FieldDiffEntry[],
    emailSubjectDiff: FieldDiffEntry[],
    emailBodyDiff: LineDiffEntry[],
    stats: {
      content: { added, removed, unchanged },
      subject: { ... },
      emailSubject: { ... },
      emailBody: { ... }
    }
  }
  ```
- Validation: 400 if either `id1` or `id2` is missing; 400 if `id1 === id2`; 404 if either template doesn't exist in the DB.

### Compare dialog (`template-compare-dialog.tsx`)
- Props: `open`, `onOpenChange`, optional `templateId1`, optional `templateId2`.
- Two shadcn Select dropdowns (Template A / Template B) with the template's code badge + version subtitle. The currently-selected counterpart is disabled in each list to prevent comparing a template with itself.
- Defaults: if no explicit `templateId1`/`templateId2` props are passed, the dialog auto-selects the two most recently updated templates (sorted by `updatedAt` desc) once the template list loads.
- State sync uses the React-documented "adjust state when props change" pattern (tracking `prevOpen` / `prevTplCount` during render) instead of `useEffect` + `setState` — this avoids the `react-hooks/set-state-in-effect` lint error that eslint-config-next enforces.
- Statistics bar at the top of the diff view: "Content diff:" label + three pill badges (added = green +, removed = red −, unchanged = gray =) with counts, plus a smaller email-body summary on the right when applicable.
- Two metadata cards (Template A on the left in rose-tinted border, Template B on the right in emerald-tinted border) showing name, code, type, version, status, and "Updated {date}".
- Inline token-level diffs for the short string fields (`subject`, `emailSubject`) — additions get a green highlight, removals get a red highlight + line-through, unchanged tokens render in normal foreground. Rendered as a single flowing paragraph (not split into lines).
- Side-by-side diff view for `content` and `emailBody`:
  - Two-column grid with column headers (Template A | Template B).
  - Each LCS diff entry is split into rows: unchanged → aligned in both columns; removed → left column only with red bg + `−` marker; added → right column only with green bg + `+` marker. Empty cells get a muted background.
  - Monospace font, 11.5px, whitespace-preserving, with up to 55vh max-height scroll.
  - Cell text uses `break-words` so long URLs/HTML attributes don't blow out the layout.
- Loading states: "Loading templates…" spinner while the list fetches, "Computing diff…" spinner while the compare fetches.
- Empty state when no templates are picked: icon + "Select two different templates" hint.
- Error state: rose-tinted banner with the error message.
- Close button in the footer.
- Mobile responsive: the pickers collapse to a single column on small screens (the arrow icon hides below `md`), and the side-by-side diff scrolls horizontally if needed.

## Issues encountered

1. **Dev server was dead on arrival.** No process was running on port 3000 when I started, despite the task instructions saying "the dev server is already running". I restarted it via `nohup /tmp/start-dev.sh` (a wrapper that calls `setsid bun run dev`). The dev server doesn't survive between Bash tool calls (the supervisor kills the orphaned process tree when the shell exits), so I had to start it inside the same Bash call as my smoke tests. Not a blocker — just an environment quirk.

2. **pdfkit `switchToPage` out of bounds.** First version of the directory-pdf endpoint returned HTTP 500 with `Error: switchToPage(1) out of bounds, current buffer covers pages 9 to 9`. Root cause: pdfkit only buffers the current page by default; older pages are flushed on `addPage()`. Fix: set `bufferPages: true` in the PDFDocument constructor. After the fix, `switchToPage(n)` can reach any page in `0..count-1` and the `bufferedPageRange().count` reflects the true total.

3. **TOC page-number column was rendering placeholder values twice.** Initial implementation wrote a placeholder page number during the TOC skeleton pass, then tried to clear it with a white rect during the backfill pass. pypdf's text extraction saw both (the white rect only covers visually, the text operators are still there). Fix: stopped writing the placeholder entirely — the TOC skeleton now leaves the page-number column blank, and the backfill pass writes the real numbers cleanly on top of nothing.

4. **TS error on `doc.widthOfString()`.** First attempt called `doc.widthOfString(s.name, { font: "Helvetica-Bold" })` to measure the dept name for the dotted leader line. pdfkit's `TextOptions` type doesn't include a `font` property. Fix: set the font first with `doc.font("Helvetica-Bold").fontSize(11)`, then call `doc.widthOfString(s.name)` which uses the currently-set font.

5. **`react-hooks/set-state-in-effect` lint error.** First version of the compare dialog used two `useEffect`s that called `setState` synchronously — one to sync `sel1`/`sel2` from the parent's `templateId1`/`templateId2` props on open, and one to auto-pick the two most recently updated templates when the list loaded. eslint-config-next flags this as a cascading-render risk. Fix: replaced both effects with the React-documented "adjust state when prop changes" pattern (tracking `prevOpen` and `prevTplCount` in state, then calling `setState` during render when the tracked value differs from the new prop). Same UX, no lint warning, no cascading renders.

6. **Compare dialog was fetching `/api/document-templates?status=ALL`** which the existing API interprets as `where.status = "ALL"` (returning 0 templates, since no template has that literal status). Fix: removed the `?status=ALL` query param and rely on the endpoint's default behaviour (excludes only `ARCHIVED` templates).
